KEY ARCHITECTURAL HIGHLIGHTS TO AUDIT
-----------------------------------------------------------------------
1. Serverpod 4 Backend (`sanctuary_server/sanctuary_server_server`):
   - Protocol models defined in `.spy.yaml` and generated:
     - `reflection_post.spy.yaml`: maps `ReflectionPost` to PostgreSQL table `reflection_posts` with composite index `space_created_idx` over `(spaceKey, createdAt)`.
     - `quiet_digest.spy.yaml`: server-side aggregation data model.
   - Endpoints doing real backend computation (`lib/src/reflections/reflection_endpoint.dart`):
     - `publishReflection`: content validation, tone check, PostgreSQL persistence (`ReflectionPost.db.insertRow`), and WebSocket broadcast via `session.messages.postMessage('space_${post.spaceKey}', post)`.
     - `affirmCare`: atomic increments of care affirmation counts in PostgreSQL (`ReflectionPost.db.updateRow`) with live channel broadcast.
     - `watchSpace`: subscribes to real-time streams via `session.messages.createStream<ReflectionPost>('space_$spaceKey')` with automatic 4-room initial database seeding.
     - `getQuietDigest`: server-side aggregation computing total posts, care metrics, predominant intent, and calm-tech tone validation.
2. Flutter Client & Resilient Architecture (`lib/main.dart`):
   - Wired to `sanctuary_server_client` and `serverpod_client: ^4.0.4`.

   - 800ms Resilient Fallback: If opened without a local Serverpod instance running, automatically fails over to offline-first seeded calm-tech data within 800ms so judges never encounter a blank page or broken loader.
